# WiFi Transfer — 同一 WiFi 下手机 ↔ 电脑互传工具

一个跑在本机的局域网文字 / 文件互传小工具。手机和电脑连上同一个 WiFi，各自打开一个网页，就能像微信聊天一样实时互发文字和文件——不用装 App、不用数据线、不经过任何第三方服务器。

## ✨ 特性

- **微信式聊天界面**：气泡消息实时出现在双方页面，自己发的靠右（绿色），对方发的靠左（白色）。
- **文字 + 文件**：文字、图片、视频、音频、文档、压缩包都能发，单批最多 20 个文件。
- **实时同步**：基于 SSE（Server-Sent Events），发送、删除、清空都会实时推送到所有页面，断线自动重连。
- **图片预览**：图片消息显示缩略图，点击可打开大图。
- **上传进度**：文件通过 XHR 上传，实时显示进度条、速度和耗时。
- **拖拽 / 粘贴上传**：把文件拖进窗口，或直接 `Ctrl+V` 粘贴截图即可发送。
- **头像同步**：手机、电脑可分别设置头像，存服务端、两端同步（限 500KB），未设置时用 📱 / 💻 emoji 兜底。
- **历史持久化**：最近 200 条记录存到 `history/history.json`，刷新不丢；支持单条删除和一键清空。
- **中文文件名修复**：对原始文件名做多编码猜测 + 打分选优，避免上传后中文乱码。
- **局域网地址提示**：电脑端可一键复制手机访问地址。
- **纯 http 可用**：不依赖仅 https 可用的 API，移动优先，适配 iOS 安全区。
- **提示音与 Toast**：Web Audio 合成发送 / 接收双音提示，操作有反馈提示。

## 🛠 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Node.js + Express 5 + multer + cors |
| 实时推送 | SSE（浏览器 EventSource） |
| 前端 | 单文件原生 HTML / CSS / JS（无框架、无构建） |
| 存储 | 本地文件系统（`uploads/`、`history/`、`avatars/`） |

## 🚀 快速开始

### 环境要求

- Node.js 18+（Express 5 的最低要求）
- 手机与电脑处于同一 WiFi

### 启动

```bash
# 1. 安装依赖
npm install

# 2. 启动服务（二选一）
npm start       # 直接启动
npm run dev     # 监听文件变化，改代码自动重启
```

Windows 用户也可以直接双击 `start.bat`，会自动打开浏览器。

启动后控制台会打印两个地址：

```
🖥  电脑端:     http://localhost:3000
📱 手机浏览器: http://192.168.x.x:3000
```

### 使用

1. **电脑端**：浏览器打开 `http://localhost:3000`。
2. **手机端**：浏览器打开控制台打印的局域网地址（如 `http://192.168.1.10:3000`），电脑端顶部菜单也可一键复制该地址。
3. 页面会自动按 UA 判断设备类型（手机 / 电脑），也可在右上角 `⋯` 菜单里手动切换「当前设备」和「发送身份」。
4. 输入文字回车发送；点 `＋` 选文件（可多选）、拖文件进窗口、粘贴截图均可发送。

> 手机打不开时检查：两端是否同一 WiFi、电脑防火墙是否放行端口、路由器是否开启了 AP 隔离 / 访客网络隔离。

## ⚙️ 配置

| 配置项 | 方式 | 默认值 |
|---|---|---|
| 端口 | 环境变量 `PORT` | `3000` |
| 监听地址 | 固定 | `0.0.0.0` |
| 历史记录上限 | `server.js` 中的 `MAX_HISTORY_ITEMS` | `200` |
| 单批文件数 | multer `limits.files` | `20` |
| 头像大小 | 前端 + multer 双重限制 | `500KB` |

自定义端口：`PORT=8080 npm start`

## 🔌 API 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/events` | SSE 事件流：`ready` / `ping` / `history` |
| `POST` | `/api/message` | 发送文字，body：`{text, sender, clientId}` |
| `POST` | `/api/upload` | 上传文件，multipart 字段 `files`（最多 20 个） |
| `GET` | `/api/history` | 获取历史记录 `{items: [...]}` |
| `DELETE` | `/api/history` | 清空全部记录并删除对应物理文件 |
| `DELETE` | `/api/history/:id` | 删除单条记录（文件记录同时删物理文件） |
| `GET` | `/api/info` | 获取局域网地址 `{ip, port, url}` |
| `GET` | `/api/avatars` | 获取已设置头像 `{phone?, computer?}` |
| `POST` | `/api/avatars/:sender` | 上传头像（`phone` / `computer`，≤500KB） |
| `DELETE` | `/api/avatars/:sender` | 删除头像 |

SSE 广播的事件格式：

```js
{ action: 'upsert' | 'delete' | 'clear', entry?, id? }
```

## 🔍 实现要点

- **消息去重**：每条记录带 `clientId`，前端收到 SSE 回声时按 `id` 去重并跳过自己发的消息，避免重复渲染。
- **文件名修复**：多候选解码（原始值 / `decodeURIComponent` / latin1→utf8 / binary→utf8）后打分选优，再清洗非法字符。
- **头像跨端**：统一存为 `avatars/{phone|computer}.jpg`，两端读同一份文件；图片 URL 带时间戳参数做缓存击穿。
- **禁缓存**：静态资源与上传目录带 `no-store` 类响应头，避免浏览器用旧缓存。
- **音频解锁**：首次用户交互后才初始化 Web Audio，符合浏览器自动播放策略。
- **顶部未读数字**：`1334` 是写死的静态展示（仿微信红点效果），不随操作变化。

## ⚠️ 注意

- 仅适合**可信局域网**：接口无鉴权，同网段任何人都能访问或清空记录。
- 数据只保存在运行服务的这台电脑上，换机器不会带走历史和文件。
- 历史超过 200 条会自动淘汰最旧记录；删除记录会同时删除对应磁盘文件，不可恢复。
