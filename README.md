# WiFi Transfer

> **局域网实时文字与文件互传工具** · Node.js / Express 5 · 微信风格聊天界面 · SSE 实时推送 · 零外部依赖

WiFi Transfer 是一个面向局域网场景的轻量级双向互传服务。服务在电脑本机启动后，处于同一 WiFi 下的手机与电脑只需通过浏览器访问即可建立通信，文字消息与各类文件以聊天气泡的形式实时呈现在双方页面。整个数据链路在局域网内闭环，无需安装客户端、不经过第三方服务器，兼顾使用便捷性与数据私密性。

## 项目概述

| 维度 | 说明 |
|---|---|
| **应用场景** | 同一 WiFi 下手机与电脑之间的临时文字、图片及文件交换，替代数据线与社交软件传文件 |
| **核心定位** | 零安装、零配置、开箱即用的局域网双向通信工具 |
| **技术架构** | Express 5 提供 HTTP API 与 SSE 服务端推送，multer 负责文件上传，前端为原生单文件实现 |
| **数据策略** | 文件、历史记录与头像全部落盘本地文件系统，不依赖数据库及任何外部服务 |

## ✨ 核心特性

- **微信式聊天界面**：气泡消息实时出现在双方页面，自己发的靠右（绿色），对方发的靠左（白色）。
- **文字 + 文件**：文字、图片、视频、音频、文档、压缩包都能发，单批最多 20 个文件。
- **实时同步**：基于 SSE（Server-Sent Events），发送、删除、清空都会实时推送到所有页面，断线自动重连。
- **图片预览**：图片消息显示缩略图，点击可打开大图。
- **上传进度**：文件通过 XHR 上传，实时显示进度条、速度和耗时。
- **拖拽 / 粘贴上传**：把文件拖进窗口，或直接 `Ctrl+V` 粘贴截图即可发送。
- **头像同步**：手机、电脑可分别设置头像，存服务端、两端同步（限 500KB），未设置时用 📱 / 💻 emoji 兜底。
- **历史持久化**：最近 200 条记录存到 `history/history.json`，刷新不丢；支持单条删除和一键清空。
- **中文文件名修复**：对原始文件名做多编码猜测 + 打分选优，避免上传后中文乱码。
- **局域网地址提示**：电脑端可一键复制手机访问地址。
- **纯 http 可用**：不依赖仅 https 可用的 API，移动优先，适配 iOS 安全区。
- **提示音与 Toast**：Web Audio 合成发送 / 接收双音提示，操作有反馈提示。

## 🏗 技术架构

整体采用「薄服务端 + 零构建前端」的分层结构：服务端只负责 API 与文件落盘，界面与交互全部收敛在浏览器端的一个原生 HTML 文件里，没有构建链、没有前端框架依赖。

| 层 | 选型 | 说明 |
|---|---|---|
| 运行时 | Node.js 18+ | Express 5 的最低要求 |
| Web 框架 | Express 5 | 路由、静态服务、统一错误处理中间件 |
| 文件上传 | multer（`diskStorage`） | 流式落盘，避免大文件占用内存 |
| 实时推送 | SSE + 原生 `EventSource` | 服务端单向广播，浏览器自带断线重连 |
| 前端 | 原生 HTML / CSS / JS 单文件 | 无框架、无构建、无打包产物 |
| 存储 | 本地文件系统 | `uploads/` `history/` `avatars/`，零数据库依赖 |

### 通信模型

系统本质是「请求-响应」与「单向推送」的混合模型：

- **上行（客户端 → 服务端）**：发文字走 `POST /api/message`，发文件走 `POST /api/upload`（用 XHR 以便实时上报进度），都是普通 HTTP 请求。
- **下行（服务端 → 客户端）**：`GET /api/events` 建立一条长连接 SSE 通道，服务端以 `event: history` 广播 `{action, entry, id}` 增量事件，客户端据此更新视图。
- **为什么选 SSE 而非 WebSocket**：本场景的消息流是单向的——只有服务端需要主动推，客户端的写操作天然是 HTTP 请求。SSE 基于纯 HTTP，能穿透常见代理与防火墙；浏览器 `EventSource` 原生支持断线自动重连，配合 20s 心跳（`event: ping`）保活，无需引入额外依赖或自建连接保活逻辑，对局域网工具是更轻量的选择。
- **回声抑制**：每条记录携带 `clientId`，客户端收到广播后先按 `id` 去重，再跳过 `clientId` 与自己相同的条目，避免自己发的消息重复渲染。

### 上传管线

- **流式落盘**：multer `diskStorage` 直接写磁盘，文件名规则 `{时间戳}_{随机串}_{安全文件名}`——时间戳保序、随机串防重名、安全名保可读。
- **中文文件名修复**：对 `originalname` 生成多个解码候选（原值 / `decodeURIComponent` / latin1→utf8 / binary→utf8），按启发式打分选优——含 CJK 字符加分、含 `U+FFFD` 乱码字符重罚、含非法路径字符减分——再清洗替换非法字符。解决 multipart 头在不同浏览器 / 系统下编码不一致导致的中文名乱码问题。
- **分类与 MIME**：扩展名 + 上报 MIME 双重判定，遇到 `octet-stream` 回退到内置扩展名映射表，归类为 image / video / audio / other，驱动前端差异化渲染。

### 一致性与缓存

- **写时持久化**：每次变更立即全量写回 `history.json`，200 条滑动窗口淘汰最旧记录；重启从磁盘读回，内存与文件同源。
- **文件生命周期绑定**：删除单条或清空记录时同步 `unlink` 对应物理文件，避免孤儿文件堆积。
- **缓存策略**：静态资源统一挂 `no-store` 响应头；头像统一存为 `avatars/{phone|computer}.jpg`，两端读同一份文件，URL 追加时间戳参数做缓存击穿，确保跨设备上传后各端立即看到新头像——局域网 HTTP 环境下浏览器缓存是「改了不生效」的常见元凶。
- **移动端适配**：UA 嗅探区分 phone / computer，决定气泡方向与身份默认值；布局走 CSS 响应式 + `env(safe-area-inset-*)` 适配 iOS 安全区，输入框自动增高。

### 前端交互细节

- **音频解锁**：Web Audio 上下文在首次用户交互后才初始化，符合浏览器自动播放策略，避免提示音被静默拦截。
- **静态未读徽标**：顶部左侧的 `1334` 是写死的视觉元素（仿微信红点），不参与任何计数逻辑。
- **复制兼容**：优先使用 `navigator.clipboard`，http 环境下降级到 `textarea` + `execCommand('copy')`。

## 🚀 快速开始

### 环境要求

- Node.js 18+（Express 5 的最低要求）
- 手机与电脑处于同一 WiFi

### 启动

```bash
# 1. 安装依赖
npm install

# 2. 启动服务（二选一）
npm start       # 直接启动
npm run dev     # 监听文件变化，改代码自动重启
```

Windows 用户也可以直接双击 `start.bat`，会自动打开浏览器。

启动后控制台会打印两个地址：

```
🖥  电脑端:     http://localhost:3000
📱 手机浏览器: http://192.168.x.x:3000
```

### 使用

1. **电脑端**：浏览器打开 `http://localhost:3000`。
2. **手机端**：浏览器打开控制台打印的局域网地址（如 `http://192.168.1.10:3000`），电脑端顶部菜单也可一键复制该地址。
3. 页面会自动按 UA 判断设备类型（手机 / 电脑），也可在右上角 `⋯` 菜单里手动切换「当前设备」和「发送身份」。
4. 输入文字回车发送；点 `＋` 选文件（可多选）、拖文件进窗口、粘贴截图均可发送。

> 手机打不开时检查：两端是否同一 WiFi、电脑防火墙是否放行端口、路由器是否开启了 AP 隔离 / 访客网络隔离。

## ⚙️ 配置

| 配置项 | 方式 | 默认值 |
|---|---|---|
| 端口 | 环境变量 `PORT` | `3000` |
| 监听地址 | 固定 | `0.0.0.0` |
| 历史记录上限 | `server.js` 中的 `MAX_HISTORY_ITEMS` | `200` |
| 单批文件数 | multer `limits.files` | `20` |
| 头像大小 | 前端 + multer 双重限制 | `500KB` |

自定义端口：`PORT=8080 npm start`

## 🔌 API 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/events` | SSE 事件流：`ready` / `ping` / `history` |
| `POST` | `/api/message` | 发送文字，body：`{text, sender, clientId}` |
| `POST` | `/api/upload` | 上传文件，multipart 字段 `files`（最多 20 个） |
| `GET` | `/api/history` | 获取历史记录 `{items: [...]}` |
| `DELETE` | `/api/history` | 清空全部记录并删除对应物理文件 |
| `DELETE` | `/api/history/:id` | 删除单条记录（文件记录同时删物理文件） |
| `GET` | `/api/info` | 获取局域网地址 `{ip, port, url}` |
| `GET` | `/api/avatars` | 获取已设置头像 `{phone?, computer?}` |
| `POST` | `/api/avatars/:sender` | 上传头像（`phone` / `computer`，≤500KB） |
| `DELETE` | `/api/avatars/:sender` | 删除头像 |

SSE 广播的事件格式：

```js
{ action: 'upsert' | 'delete' | 'clear', entry?, id? }
```

## ⚠️ 注意

- 仅适合**可信局域网**：接口无鉴权，同网段任何人都能访问或清空记录。
- 数据只保存在运行服务的这台电脑上，换机器不会带走历史和文件。
- 历史超过 200 条会自动淘汰最旧记录；删除记录会同时删除对应磁盘文件，不可恢复。
